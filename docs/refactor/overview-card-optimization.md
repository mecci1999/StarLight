# Overview 面板卡片布局优化方案

## 目标

在不改变当前 Overview 数据模型（panel + widgets）的前提下，优化首页卡片布局与信息表达方式，让用户在首屏更快回答三个问题：

1. 当前整体状态怎么样
2. 最近是否有异常波动
3. 哪些对象值得立刻点击进去看

本方案不直接涉及接口改造，重点聚焦于展示结构、卡片层级、指标表达与交互密度控制。

---

## 当前问题总结

基于 `src/domains/overview/pages/OverviewPage.tsx` 的现状和参考截图，可归纳出以下问题：

### 1. KPI 卡片信息过于“文字化”

当前指标摘要卡片普遍采用：
- 主值
- baseline 文本
- delta 文本
- 环比文本
- 阈值 tag

问题在于：
- `baseline / delta / 环比` 都是纯文字，用户需要逐行阅读后才能理解含义
- “变化趋势”没有被视觉强化，箭头只是附着在文本中，信息优先级不够
- 主值旁边缺少更直观的对比载体，例如微趋势、占比环、色带、状态条

### 2. 卡片类型没有形成明确层级

当前 Overview 中：
- KPI 摘要卡
- 风险服务列表
- 事件列表
- 接入状态
- 趋势图
- 快捷入口

虽然功能齐全，但模块之间的“阅读顺序”不够稳定。用户进入页面后，不容易一眼看出：
- 哪一块是“总览层”
- 哪一块是“异常层”
- 哪一块是“钻取层”

### 3. 风险/事件卡片可点击，但点击价值没有被强化

风险服务和事件列表虽然能跳转，但视觉上更像普通列表，而不是“需要优先处理的对象”。

### 4. 趋势类卡片缺少“当前值 + 趋势图”的组合表达

当前趋势图已经存在，但卡片标题区缺少：
- 当前值
- 对比值
- 波动方向
- 异常标识

导致趋势图像“单独一张图”，而不是“一个完整指标组件”。

### 5. 快捷入口和接入状态的表现形式偏功能面板，不够首页化

这两类卡片更像“工具区”，但现在和 KPI、事件列表混排后，会弱化首页的监控主线。

## 参考主流看板产品后的推荐结构

结合你给的参考截图，以及主流监控/看板产品（Datadog / Grafana / New Relic / 云厂商控制台）的常见做法，推荐把 Overview 页面拆成三层结构：

## 第一层：总览层（回答“现在整体怎么样”）

建议保留 4 个最关键 KPI，但每张卡都从“纯文字说明”改成“主值 + 微趋势 + 状态语义”。

建议卡片：
- 服务总数
- 健康服务数
- 活跃告警
- 请求量 / P95 / 错误率 中最重要的 1~2 个

### 推荐卡片结构

每张卡片建议改成：

- 左上：指标标题
- 右上：状态徽标（正常 / 波动 / 告警）
- 中间：主值（大数字）
- 下方：
  - 同比/环比箭头 + 百分比
  - 迷你趋势线（sparkline）
  - 次要信息（baseline）

### 具体建议

#### 服务总数 / 健康服务数
不再强调“baseline / delta / 环比”三段文字。
建议改为：
- 主值：11
- 副值：健康 11 / 异常 0
- 右侧：小环形占比图或进度条（健康占比）
- 底部：较上周期 +0 / -1 这种单行简写

#### 活跃告警
建议强化“事件紧急度”而不是只写数字：
- 主值：当前活跃 3
- 副值：Critical 1 / Warning 2
- 右上：红色状态点
- 底部：较上一时段 +2

#### 错误率 / P95 / 请求量
建议统一成“标题 + 当前值 + 微趋势图 + 变化方向”。
避免在同一张卡上出现太多解释性文字。

---

## 第二层：波动层（回答“哪里有变化/异常”）

这一层建议放最值得关注的“趋势”和“异常对象”，优先展示：
- 风险服务
- 事件列表
- 请求/错误/延迟趋势

### 推荐布局

- 左侧 2/3：趋势图区域
- 右侧 1/3：风险服务 / 活跃事件

这样用户先看整体波动，再看异常落点，比现在更符合监控首页的思维路径。

### 趋势图建议

每张趋势图卡片的头部增加：
- 指标名称
- 当前值
- 与上一时段对比值
- 时间范围说明

即采用：

- 标题：请求量趋势
- 当前值：12.4k
- 对比：+8.2%
- 图表：折线 / 面积线

这样趋势图不再只是“图”，而是完整的信息模块。

### 风险服务建议

每一条风险服务建议突出：
- 服务名
- 健康状态 badge
- 当前最重要异常（错误率 / 延迟变化 / 活跃事件）

推荐改为双层结构：
- 第一行：服务名 + 健康 badge
- 第二行：关键风险摘要（例如：错误率 2.4%，活跃事件 3）

不要让“Health unknown / 延迟变化 +12ms / 活跃事件 1”全部放在一句长文案里。

### 事件列表建议

每条事件建议结构化成：
- 左侧：severity 色条 / 点
- 中间：标题 + 摘要
- 右侧：时间 + 来源

这样比现在只靠一段标题/摘要更容易扫读。

---

## 第三层：行动层（回答“接下来点哪里”）

这一层建议放：
- 快捷入口
- 接入状态
- 未来扩展 widget

但它不应该和总览层抢视觉优先级。

### 快捷入口建议

不要做成和风险服务同等强调的“卡片列表”。
更适合：
- 小型 action card
- icon + label + 说明
- 作为“常用跳转区”集中放在一排

### 接入状态建议

接入状态本质上是“系统就绪度面板”，更适合作为一张独立状态卡：
- metrics/logs/traces 三个通道并排
- 每个通道展示状态点 + 最后更新时间 / 成功率
- 底部统一给 dropped / delayed / failed 概览

而不是每个值都平铺成相同权重的文本块。

## 具体的卡片表达优化建议

## 1. 环比 / baseline / delta 的表达方式

### 当前问题
大量使用：
- baseline xxx
- delta xxx
- 环比 xxx

这种表达需要逐字阅读，且用户不容易快速比较多个卡片。

### 推荐替代方式

#### A. 箭头 + 百分比
例如：
- ↑ 8.2%
- ↓ 3.4%
- → 持平

只保留最关键变化结论，不把“delta”作为文字标签单独写出。

#### B. 迷你趋势线（sparkline）
在 KPI 卡底部放一条 24h / 7d 微趋势线。
用户一眼就能看出：
- 上升
- 下降
- 波动异常
- 平稳

#### C. 占比图替代长文本
例如“健康服务数”不用写：
- baseline: 总数 11
- 环比: 占比 100%

而改为：
- 主值：11
- 副值：11 / 11
- 旁边小环图：100%

#### D. 颜色语义替代解释性文字
- 正常：绿色
- 关注：橙色
- 异常：红色
- 未知：灰色

让用户先看颜色，再读文字。

## 2. KPI 卡的推荐标准模板

推荐统一成以下模板：

### KPI Card V2
- 顶部：
  - 标题
  - 状态 badge
- 中部：
  - 主值
- 底部：
  - 趋势箭头 + 百分比
  - sparkline
  - 次要说明（可选）

### 适用指标
- 服务总数
- 健康服务数
- 活跃告警
- 请求量
- 错误率
- P95 延迟
- ingest 成功率

---

## 3. 页面布局推荐草案

建议最终采用以下首页结构：

### Row 1: 总览 KPI
4 张核心卡片，横向平铺。

### Row 2: 趋势 + 风险
- 左：请求 / 错误 / 延迟趋势（占更宽区域）
- 右：风险服务 + 活跃事件（纵向堆叠）

### Row 3: 系统就绪度 + 行动入口
- 左：接入状态
- 右：快捷入口

### Row 4: 可扩展区
给未来自定义 widget、实验性模块或角色专属面板使用。

## 对当前 `OverviewPage` 的落地建议

## 第一阶段（低风险）
仅改展示，不改数据模型：
- KPI 卡从文字型改成“主值 + 趋势 + 状态”
- 风险服务和事件列表重排层级
- 快捷入口和接入状态下沉到行动层
- 趋势图增加当前值和变化说明

## 第二阶段（中风险）
扩展 widget 配置能力：
- KPI widget 支持 `showSparkline`
- KPI widget 支持 `showRatioRing`
- trend widget 支持 `currentValuePlacement`
- incident widget 支持 `compact / detailed` 两种布局

## 第三阶段（高价值）
把 panel/widget 系统做成真正可配置的首页模板：
- admin/system 首页
- 普通用户首页
- 接入前首页
- 角色化 preset 首页

---

## 与现有代码结构的对应关系

当前代码里最应该优先优化的是：
- `OverviewPage.tsx` 中 `kpiCards` 的展示方式
- `renderMetricSummary()`
- `renderRiskService()`
- `renderIncidentList()`
- `renderTrendWidget()`
- `renderQuickPivot()`
- `renderIngestStatus()`

因为这几个函数已经天然对应首页的核心模块，只需要改“展示层表达”，不需要重构整个 panel 模型。

---

## 最终建议

如果只选一个最值得先做的方向，我建议优先做：

**把首页 KPI 卡从“文字说明卡”升级成“状态驱动卡”**。

原因很简单：
- 它对首屏观感影响最大
- 改动范围最集中
- 不依赖后端新增接口
- 最容易让用户立刻觉得“更直观了”
